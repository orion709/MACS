# ТЕХНИЧЕСКОЕ ЗАДАНИЕ: MACS (Monitor And Control Servers)

## 1. Общие сведения о проекте
* **Назначение:** Кроссплатформенный асинхронный клиент для мониторинга и удаленного контроля серверов по протоколу SSH.
* **Этап разработки:** Разработка MVP-версии с графическим интерфейсом (GUI).
* **Архитектурный вектор:** Реализация на базе паттерна **MVC (Model-View-Controller)** с использованием парадигмы Qt Model/View.
* **Стратегия миграции на TUI:** Чтобы в будущем перенести проект на фреймворк **Textual**, слой Модели (Model) проектируется как независимый поставщик данных. При переходе на Textual заменяются слои View и Controller, а Модель адаптируется под систему реактивных свойств TUI.
* **Формат приложения:** Запуск исключительно в виде скрипта через исполняемый файл `main.py`.

---

## 2. Используемый стек технологий и библиотеки
* **Язык программирования:** `Python 3.15`
* **Графическая оболочка (GUI):** `PyQt6` (модули `QtWidgets` для отображения, `QtCore` для сигналов).
* **Асинхронный движок:** `asyncio` (встроенный) + **`qasync`** (для интеграции событийного цикла asyncio в цикл обработки событий Qt).
* **Протокол SSH:** **`asyncssh`** (для асинхронного выполнения команд, создания каналов и управления сессиями).
* **База данных:** **`aiosqlite`** (асинхронная работе с SQLite без блокировки потока интерфейса).
* **Безопасность и шифрование:** `cryptography` (симметричное шифрование AES для защиты конфиденциальных данных).

---

## 3. Архитектура проекта и принцип обмена данными (MVC)

Приложение разделяется на три автономных слоя согласно классическому паттерну MVC:

* **Model (Модель):** Содержит бизнес-логику (SSH, БД, шифрование). Хранит состояние приложения (списки серверов, статус подключений). При изменении состояния Модель рассылает уведомления через `pyqtSignal` в PyQt6. Она полностью изолирована от элементов интерфейса.
* **View (Представление):** Пассивный графический интерфейс (окна, вкладки, списки). Подписывается на сигналы Модели. При получении сигнала от Модели View считывает новые данные и автоматически обновляет элементы экрана. Сама View данные не обрабатывает. View принимает ввод от пользователя и передает его в Контроллер.
* **Controller (Контроллер):** Перехватывает действия пользователя из View (нажатия кнопок, ввод текста, выбор сервера в списке). Контроллер валидирует эти действия и вызывает соответствующие асинхронные методы Модели с использованием декоратора `@asyncSlot()` из библиотеки `qasync`. Контроллер не меняет интерфейс напрямую, его задача — изменить состояние Модели.

## 4. Требования к безопасности и базе данных
* **Технология БД:** Локальное хранилище на базе SQLite, работающее через асинхронную библиотеку `aiosqlite`.
* **Область хранения:** В БД сохраняется конфигурация серверов (IP, порты, логины), структура открытых пользователем вкладок, а также шаблоны bash-команд.
* **Шифрование ключей и секретов:** **Запрещено хранение паролей и приватных SSH-ключей в базе данных в открытом (текстовом) виде.** 
  * Все учетные данные перед записью в SQLite должны шифроваться алгоритмом симметричного шифрования AES с помощью библиотеки `cryptography`.
  * Ключ шифрования генерируется при первом запуске приложения и защищается либо мастер-паролем пользователя, либо локальными механизмами ОС.

## 5. Требования к UI и принципы окон (GUI-версия)
Интерфейс строится по принципу единого рабочего пространства на базе `QMainWindow`.

* **Главное окно (Основной экран):**
  * **Левая панель (Менеджер серверов):** Реализуется через виджет `QListView` или `QTreeView`, подключенный к Модели данных серверов. Панель должна автоматически скрываться (коллапсировать) при выведения курсора из зоны реагирования панели.
  * **Окно добавления сервера:** Модальное диалоговое окно (`QDialog`), запрашивающее: IP/Хост, Порт, Логин, тип авторизации (Пароль или Приватный ключ). Ввод передается Контроллеру для записи в Модель.
  * **Верхняя панель управления:** Система переключения вкладок (`QTabWidget`), позволяющая группировать терминалы.
  * **Центральная область:** Интерактивное поле терминала. Должно поддерживать базовый парсинг ANSI-последовательностей цветов и разметки для корректного рендеринга `htop`/`btop`.
* **Принцип работы вкладок:** При открытии нового терминала для уже подключенного сервера Контроллер дает команду Модели открыть новый независимый асинхронный канал (SSH Channel) внутри уже существующей сессии (SSH Connection), не создавая новое TCP-соединение.

## 6. Функциональные требования

### 6.1. Текущая базовая реализация (MVP)
1. Добавление сервера с поддержкой двух типов аутентификации (пароль / приватный ключ).
2. Автоматическая генерация пары SSH-ключей на стороне клиента и их автоматическое добавление на целевой сервер при первом входе (через пароль).
3. Поддержка мульти-вкладочности: запуск нескольких независимых терминалов к одному или разным серверам одновременно.
4. Главная страница (дашборд) подключенного сервера: автоматический запуск и интерактивное отображение утилит `btop`/`htop` (либо кастомного скрипта мониторинга системы).

### 6.2. Опциональный функционал (Развитие системы)
Каждая фича ниже реализуется в виде нового типа вкладки (View), подписанной на соответствующий модуль Модели:
* **Управление СУБД:** UI-интерфейс для просмотра таблиц, структуры и данных БД, развернутых на сервере, без ручного ввода SQL-команд.
* **Docker-панель:** Отображение списка контейнеров (`docker ps`), их статуса, ресурсов и кнопки управления (старт, стоп, рестарт, чтение логов).
* **Live-логи:** Вкладка для стриминга системных логов (например, `tail -f /var/log/syslog`) через асинхронный генератор в Модели.
* **Менеджер Systemd:** Список системных юнитов и служб, отображение их статуса (active/failed) и управление ими (`systemctl start/stop`).
* **Файловый менеджер и редактор:** Дерево директорий сервера (`/etc` и др.) с возможностью открыть текстовый файл во встроенном редакторе.
* **Шаблонизатор автоматизации:** Создание скриптов-шаблонов в GUI и их массовое асинхронное выполнение на группе выбранных серверов одновременно.
